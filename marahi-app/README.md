# مراحي — النسخة المشتركة متعددة المستخدمين 🐪🐑🐐🐄

تطبيق ويب **مستقل** لإدارة الحلال، **قاعدة بيانات مشتركة** (Supabase) + **حسابات وصلاحيات تفصيلية**، بحيث يدخل أكثر من شخص ويُديره معاً على نفس القطيع.

> دليل فرعي مستقل تماماً عن مشروع alaoufi.me. كل ملفاته داخل `marahi-app/`، والبيانات معزولة في جداول مستقلة (`marahi_*`).

## البنية
- **الواجهة:** HTML + CSS + JavaScript صِرف (بلا أطر عمل ولا خطوة بناء) — ملفات ثابتة في `public/mrahi/`.
- **يُخدم على المسار:** `https://موقعك/mrahi` (عبر مشروع Next.js الحالي — يُنشر تلقائياً مع الموقع على Vercel).
- **الخادم/القاعدة:** Supabase (Postgres) — مصادقة + صلاحيات على مستوى الصفوف (RLS).
- لا يوجد كود خادم خاص بك؛ Supabase يتولّى المصادقة والقاعدة.
- ملفات الإعداد (`schema.sql` و هذا الدليل) في `marahi-app/`، وملفات الموقع الحيّة في `public/mrahi/`.

## الإعداد (٥ خطوات)

### ١) أنشئ مشروع Supabase
من https://supabase.com أنشئ مشروعاً (مجاني للبداية).

### ٢) أنشئ الجداول والصلاحيات
Supabase → **SQL Editor** → الصق محتوى `schema.sql` كاملاً → **Run**.
ينشئ الجداول، ودوال الصلاحيات، وسياسات RLS، ومُشغّلاً يضيف صف عضو تلقائياً لكل مستخدم جديد.

### ٣) اربط التطبيق بالمشروع
من Supabase → **Project Settings → API** انسخ:
- `Project URL`
- `anon public` key

وضعهما في ملف `public/mrahi/config.js`:
```js
window.MARAHI_CONFIG = {
  SUPABASE_URL: "https://xxxx.supabase.co",
  SUPABASE_ANON_KEY: "eyJhbGciOi...",
};
```
> هذه القيم **عامة وآمنة** للواجهة؛ الحماية الحقيقية عبر RLS.

### ٤) شغّل الموقع
- **منشور تلقائياً:** بعد دفع الكود يُنشر مع موقعك على Vercel، وتفتحه على `https://موقعك/mrahi`.
- **محلياً (Next.js):** `npm install && npm run dev` ثم افتح `http://localhost:3000/mrahi`.
> يجب فتحه عبر `http(s)` وليس `file://` (لأن المصادقة تحتاج أصلاً صحيحاً).

### ٥) عيّن أول مدير
> الدخول يكون **برقم الجوال أو اسم المستخدم + رقم سري من ٤ أرقام** (لا بريد).
> أولاً في Supabase → **Authentication → Sign In / Providers → Email** أوقِف خيار **«Confirm email»**.
> وإن كانت قاعدتك منشأة سابقاً، نفّذ ملف `auth-phone-username.sql` مرة واحدة.

1. من شاشة التطبيق اضغط **حساب جديد** وأدخل: الاسم، رقم الجوال، اسم مستخدم (اختياري)، ورقم سري من ٤ أرقام.
2. في Supabase → SQL Editor نفّذ (استبدل اسم المستخدم أو الجوال):
```sql
update public.mrahi_members
   set role='admin', is_active=true,
       perms='{"animals":{"view":true,"add":true,"edit":true,"delete":true},
               "breeding":{"view":true,"add":true,"edit":true,"delete":true},
               "vaccines":{"view":true,"add":true,"edit":true,"delete":true},
               "treatments":{"view":true,"add":true,"edit":true,"delete":true},
               "backup":{"view":true}}'::jsonb
 where username = 'اسم_المستخدم';   -- أو: where phone = '05xxxxxxxx';
```
3. أعد تسجيل الدخول — الآن أنت مدير، ومن **المزيد → المستخدمون والصلاحيات** تفعّل بقية الفريق وتمنحهم الصلاحيات بنفسك (بدون SQL).

## الأدوار والصلاحيات
- **مدير:** كل الصلاحيات + إدارة المستخدمين (تفعيل/إيقاف، ترقية، منح صلاحيات لكل قسم).
- **مستخدم:** صلاحيات **تفصيلية** يحددها المدير لكل قسم بأربع إمكانيات: **عرض / إضافة / تعديل / حذف**:
  الحلال • التلقيح/الولادات • التطعيمات • العلاجات. (النسخ الاحتياطي: عرض/تصدير فقط.)
  مفروضة على مستوى قاعدة البيانات (RLS) فلا يمكن تجاوزها من المتصفّح.
- المستخدم الجديد يبقى **بانتظار التفعيل** حتى يفعّله المدير.

## المزايا
سجل البهيمة والنسب التلقائي • التلقيح والحمل (حساب الولادة تلقائياً حسب النوع) • تسجيل الولادات وربط المواليد • أنواع التطعيمات والتطعيم (حساب التحريم) • العلاجات (حساب التحريم) • التنبيهات • البحث • تصدير JSON/CSV ومشاركة. عربي RTL بالكامل.

## ملاحظة أمان
- لا تضع **service_role key** في الواجهة إطلاقاً — فقط `anon public`.
- كل صلاحيات القراءة/الكتابة مفروضة في قاعدة البيانات عبر RLS، فلا يمكن تجاوزها من المتصفّح.
