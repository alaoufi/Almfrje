# تصميم تطبيق Android والمراسلات الفردية والتنبيهات

التاريخ: 2026-09-04

## السياق والاعتماد

لا يحتوي مستودع المفرجي حاليًا مشروع Android. الموجود موقع ويب حي وتطبيق PWA بواجهة عربية، مع خيار إضافة اختصار للشاشة ودليل زوار ودليل إدارة وأسئلة شائعة داخل `app.js`. توجد محادثات شبيهة بواتساب للمدير والمشرفين العامين، لكنها مناقشات إدارية مشتركة وليست رسائل أعضاء خاصة، ولا توجد Service Worker أو بنية Web Push حاليًا.

اعتمد المالك إنشاء APK رسمي ورابط تنزيل وتعليمات تثبيت، وتحديث دليل المستخدم ودليل الإدارة، وإضافة مراسلات فردية خاصة بين عضوين مع تنبيه عند وصول رسالة إلى التطبيق المثبت. اعتمد صراحة عدم إنشاء محادثات جماعية إطلاقًا ضمن هذا النظام.

تعتمد هذه الوثيقة على تصميم تقوية الصلاحيات وتسريع الرئيسية وتصميم تنبيهات الإجراءات وسجل التعديلات. لا ينشر APK قبل إغلاق ثغرات الوصول المعروفة ونجاح مصفوفة الصلاحيات؛ فالتطبيق قناة جديدة للموقع نفسه وليس مبررًا لتوسيع الوصول.

## الأهداف

- تمكين عضوين مفعّلين من محادثة نصية فردية خاصة وفورية بواجهة مألوفة شبيهة بواتساب.
- منع أي عضو ثالث أو مشرف أو مدير من قراءة محتوى محادثة لم يكن طرفًا فيها.
- إظهار عدد الرسائل غير المقروءة وحالة القراءة داخل التطبيق.
- إرسال تنبيه Android عند وصول رسالة جديدة بعد منح المستخدم إذن الإشعارات، بما في ذلك عندما يكون التطبيق مغلقًا.
- نشر APK رسمي موقّع مرتبط حصريًا بموقع المفرجي الحي.
- توفير صفحة تنزيل واضحة برابط ثابت، وإصدار، وحجم، وبصمة SHA-256، وتعليمات تنزيل وتثبيت وتحديث.
- تحديث دليل المستخدم ودليل الإدارة والأسئلة الشائعة بكل الميزات المعتمدة في هذا المشروع.

## خارج النطاق

- لا توجد مجموعات، ولا محادثة تضم أكثر من عضوين، ولا إنشاء مجموعة أو دعوة أعضاء.
- لا توجد صور أو فيديو أو صوت أو ملفات أو مكالمات داخل الرسائل في الإصدار الأول؛ الرسائل نصية فقط.
- لا توجد حالات يومية أو قنوات أو بث جماعي أو إعادة توجيه جماعية.
- لا يدعي النظام توفير تشفير طرف إلى طرف. الحماية المعتمدة هي HTTPS، والتحقق الخادمي، وRLS، وحصر القراءة بالطرفين.
- لا يعمل التطبيق دون اتصال لقراءة بيانات جديدة؛ يعرض شاشة اتصال واضحة ويحاول الاستعادة عند عودة الشبكة.
- لا يودع ملف APK أو مفتاح التوقيع داخل Git؛ تحفظ الإصدارات في GitHub Releases ويحفظ مفتاح التوقيع في أسرار البناء المحمية.

## البدائل التي دُرست

### تطبيق TWA موقّع مرتبط بالموقع الحي — المعتمد

يشغّل التطبيق أصل المفرجي الرسمي في تجربة Android كاملة الشاشة، مع Digital Asset Links يثبت ملكية النطاق. تبقى وظائف الموقع وتحديثاته في مصدر واحد، وتعمل Web Push ضمن أصل الموقع نفسه، ولا ننسخ منطق الصلاحيات أو البيانات إلى تطبيق منفصل.

المزايا: أقل ازدواجية، تحديثات الموقع تصل فورًا، سطح أمني أصغر، وروابط الرسائل تفتح الشاشة الصحيحة. القيود: يحتاج الإنترنت ومتصفحًا متوافقًا على Android، ويتطلب تطابق بصمة شهادة APK مع ملف `assetlinks.json`.

### غلاف Capacitor/WebView بعيد

يوفر تحكمًا أصليًا أكبر، لكنه يضيف إعداد WebView وجسرًا أصليًا ودورة تحديث مستقلة ومخاطر تنقل إلى نطاقات غير مصرح بها. لا توجد حاجة حالية تبرر هذا التعقيد.

### نسخة أصول مضمّنة داخل APK

لا تناسب التطبيق لأن نقاط API والتغييرات الأمنية والبيانات كلها حية؛ ستنشأ نسخ قديمة ومتباينة. لذلك رُفضت.

## هوية تطبيق Android

- اسم التطبيق الظاهر: `المفارجة`.
- معرف الحزمة: `me.alaoufi.almfrje`.
- الإصدار الأول: `versionName 1.0.0` و`versionCode 1`.
- `minSdk 23`، و`compileSdk 36`، و`targetSdk 36`.
- رابط البدء: أصل المفرجي الرسمي ومسار الرئيسية.
- يسمح التطبيق بالتنقل داخل أصل المفرجي فقط. الروابط الخارجية تفتح في المتصفح ولا ترث جلسة التطبيق.
- توضع أيقونة Android تكيفية وشاشة بدء من هوية الموقع الحالية من دون تغيير الشعار أو الألوان.
- يثبت `/.well-known/assetlinks.json` ارتباط النطاق بمعرف الحزمة وبصمة شهادة الإصدار.

يستهدف الإصدار Android 16/API 36 وفق الإصدار المستقر الحالي، ويثبت ويختبر على Android 6/API 23 فأحدث. إذا تعذر على أداة TWA المعتمدة بناء هذه القيم يتوقف الإصدار ويُحدّث مسار البناء؛ لا تخفض القيم بصمت. لا يضاف أي مفتاح Supabase خدمي أو VAPID خاص أو كلمة مرور إلى APK.

## نموذج المراسلات الفردية

### أهلية الاستخدام

- المراسلات متاحة للحساب المسجل ذي العضوية المفعلة والمرتبطة بشخص في الشجرة فقط.
- لا يستطيع الزائر المؤقت أو العضو الموقوف أو غير المفعّل فتح المحادثات أو إرسال رسالة أو تسجيل اشتراك Push.
- يبدأ العضو محادثة بالبحث عن عضو مفعّل بالاسم المعروض فقط؛ لا تعرض نتائج البحث رقم الجوال أو البريد أو بيانات خاصة.
- لا يستطيع العضو مراسلة نفسه.

### محادثة بين طرفين فقط

ينشأ لكل زوج أعضاء سجل محادثة واحد، مع ترتيب ثابت لمعرفيهما وقيد فريد يمنع تكرار المحادثة. لا توجد قائمة مشاركين قابلة للتوسعة، ولا يقبل الخادم أكثر أو أقل من طرفين. إضافة طرف ثالث تتطلب نوع بيانات ومسارًا غير موجودين وتفشل مغلقًا.

كل رسالة تحتوي الحد الأدنى اللازم:

- معرف الرسالة والمحادثة.
- معرف المرسل المشتق من الجلسة.
- النص المنقى، بحد أقصى 2000 حرف.
- وقت الخادم.

لا يقبل الخادم `sender_id` من المتصفح. يستنتج المرسل من الجلسة ويتحقق أنه أحد طرفي المحادثة وأن المستقبل هو الطرف الآخر المفعّل.

### تجربة الاستخدام

- شاشة `الرسائل` تعرض المحادثات بترتيب أحدث رسالة، وصورة العضو واسمه، ومعاينة قصيرة، والوقت، وعدد غير المقروء.
- شاشة المحادثة تعرض فقاعات المرسل والمستقبل، وفواصل الأيام، ووقت كل رسالة، وعلامة إرسال ثم قراءة.
- إرسال الرسالة متفائل بصريًا مع حالة `جارٍ الإرسال`، لكنه لا يعدها مرسلة حتى يؤكد الخادم حفظها.
- تتلقى الشاشة المفتوحة الرسائل فورًا عبر Supabase Realtime بعد تطبيق RLS.
- إذا تعذر Realtime، يجري تحديث خفيف كل 15 ثانية أثناء فتح شاشة المحادثة فقط، ويتوقف عند مغادرتها أو إخفاء التطبيق.
- يحدث عدد غير المقروء عند الدخول، وبعد وصول حدث، وعند استعادة التركيز إذا مرّت 60 ثانية منذ آخر تحديث.
- لا تضاف مؤشرات كتابة أو آخر ظهور أو تسجيل صوتي في هذا الإصدار.

## الخصوصية والصلاحيات

تستخدم المراسلات جداول مستقلة تمامًا عن `almfrje_topics` و`almfrje_topic_msgs` الإدارية. لا يعاد استعمال سياسات المناقشات الحالية لأنها تسمح لفئات إدارية متعددة بقراءة المحتوى.

يعتمد النموذج الجداول التالية:

- `almfrje_direct_conversations`: طرفان مرتبان، آخر رسالة ووقتها فقط.
- `almfrje_direct_messages`: الرسائل النصية ومرسلها ووقت الخادم.
- `almfrje_direct_reads`: آخر رسالة قرأها كل طرف.
- `almfrje_direct_blocks`: الحظر بين عضوين.
- `almfrje_direct_reports`: بلاغات إساءة مرتبطة برسالة محددة.
- `almfrje_push_subscriptions`: اشتراكات Push التي يملكها المستخدم على أجهزته.

تفرض RLS والدوال الخادمة:

- قراءة المحادثة ورسائلها لطرفيها فقط.
- إرسال رسالة من طرف المحادثة المفعّل فقط، وبهوية `auth.uid()` الفعلية.
- تحديث مؤشر القراءة لصاحب المؤشر فقط.
- إنشاء أو حذف اشتراك Push لصاحبه فقط.
- منع المراسلة عند وجود حظر في أي اتجاه.
- منع الأدمن والمشرف من قراءة النصوص لمجرد دورهما؛ الإدارة ليست طرفًا تلقائيًا.
- منع التعداد العام للمحادثات أو معرفة من يراسل من.

أي دالة `SECURITY DEFINER` تضبط `search_path`، وتسحب صلاحية التنفيذ من `PUBLIC` و`anon`، وتمنح فقط للمسار الموثق الذي يحتاجها. لا تستخدم واجهة العميل مفتاح الخدمة.

## الحظر والإبلاغ

- يستطيع العضو حظر الطرف الآخر من شاشة المحادثة؛ يمنع الحظر الرسائل الجديدة في الاتجاهين ولا يحذف التاريخ من حساب الطرفين.
- يستطيع العضو رفع بلاغ عن رسالة محددة مع سبب مختصر.
- لا تستطيع الإدارة تصفح المحادثات العادية. عند البلاغ فقط تحفظ نسخة محدودة من الرسالة المبلغ عنها واسم المرسل والمبلغ ووقت الرسالة لتظهر للأدمن في شاشة البلاغات.
- يرى الأدمن البلاغات ويتخذ إجراءً على الحساب وفق الصلاحيات الحالية، ويسجل كل قرار.
- لا يستطيع المبلغ تعديل النص المنسوخ أو اختيار رسالة ليست في محادثة هو طرف فيها.

## منع الإساءة والتعارض

- حد الإرسال 30 رسالة في الدقيقة لكل عضو، وحد بدء 20 محادثة جديدة في الساعة.
- يرفض النص الفارغ والنص الأطول من 2000 حرف، وينقى العرض من HTML والروابط البرمجية.
- يستخدم لكل إرسال معرف طلب فريدًا؛ إعادة المحاولة بالمعرف نفسه لا تنشئ رسالتين.
- لا يقبل إرسال جديد من عضو أوقف بعد فتح الشاشة، حتى لو بقيت جلسته محليًا.
- يعتمد وقت الخادم وترتيب المعرفات، لا ساعة الجهاز، لترتيب الرسائل.

## الإشعارات والتنبيه

### Web Push

تسجل Service Worker خاصة بأصل المفرجي وتستخدم Web Push بمفاتيح VAPID. يطلب التطبيق إذن الإشعارات من زر واضح داخل شاشة الرسائل أو إعداداتها بعد تسجيل الدخول، ولا يطلبه تلقائيًا عند أول فتح.

بعد حفظ الرسالة بنجاح يرسل الخادم تنبيهًا إلى اشتراكات الطرف المستقبل:

- العنوان: `رسالة جديدة من {اسم المرسل}`.
- الجسم الافتراضي: `افتح تطبيق المفارجة لقراءتها`، ولا يحتوي نص الرسالة حفاظًا على خصوصية شاشة القفل.
- لا يرسل تنبيهًا إلى جهاز المرسل.
- الضغط على التنبيه يفتح المحادثة المحددة بعد التحقق من الجلسة والعضوية.
- إذا كان المستقبل داخل المحادثة نفسها وواجهة التطبيق ظاهرة، يكتفى بالتحديث الداخلي ولا يظهر تنبيه مزعج.

تنظف اشتراكات Push المنتهية عند رد `404` أو `410`. لا تسجل مفاتيح الاشتراك أو نصوص الرسائل في السجلات العامة. مفتاح VAPID الخاص يبقى في أسرار Cloudflare/GitHub اللازمة ولا يرسل للمتصفح؛ المفتاح العام وحده يظهر للعميل.

### حدود الضمان

يصل التنبيه عندما يكون الجهاز متصلًا، وإذن الإشعارات مفعّلًا، وخدمات المتصفح غير مقيدة من النظام. إذا رفض المستخدم الإذن أو منع Android عمل المتصفح في الخلفية، لا يدعي التطبيق ضمان التنبيه؛ يبقى عدد غير المقروء صحيحًا ويظهر عند فتح التطبيق. يشرح دليل المستخدم كيفية تفعيل الإذن وإلغاء تقييد البطارية عند الحاجة.

## صفحة التنزيل

تضاف شاشة عامة بالمسار `#/downloads` وعنوان `التنزيلات`، ويمكن فتحها قبل الدخول وبعده، ويربط بها زر في شاشة الدخول وقائمة `المزيد`. تعرض:

- اسم التطبيق وأيقونته.
- رقم الإصدار وتاريخ النشر والحجم.
- زر `تنزيل APK للأندرويد`.
- بصمة SHA-256 كاملة مع زر نسخ.
- حالة التوقيع ومصدر الملف الرسمي.
- الحد الأدنى لإصدار Android بعد تثبيته في البناء.
- رابط `ما الجديد` وتعليمات التحديث.

تبقى صفحة `#/downloads` هي الرابط الثابت للمستخدم. يشير زرها إلى أصل إصدار مسمى بالإصدار داخل وسم GitHub Release ثابت، مثل `almfrje-1.0.0.apk` داخل وسم `almfrje-android-v1.0.0`، ولا يستبدل الأصل بعد النشر. عند إصدار نسخة جديدة يحدث زر الصفحة إلى رابط الوسم الجديد. لا يخزن الملف الثنائي في مستودع Git أو داخل نشر Cloudflare.

## شرح التنزيل والتثبيت

يعرض الدليل خطوات واضحة ومصورة نصيًا:

1. اضغط `تنزيل APK للأندرويد` من موقع المفرجي الرسمي.
2. افتح الملف بعد اكتمال التنزيل.
3. إذا طلب Android السماح للمصدر، افتح إعداد `السماح من هذا المصدر` للمتصفح الذي استُخدم فقط، ثم ارجع للتثبيت.
4. وافق على التثبيت وافتح `المفارجة`.
5. سجل الدخول وادخل شاشة الرسائل، ثم فعّل الإشعارات من الزر المخصص.
6. بعد التثبيت أعد إيقاف `السماح من هذا المصدر` إن لم تكن تحتاجه.

يوضح الدليل أن Android قد يظهر تحذيرًا لأن التوزيع مباشر خارج المتجر، وأن الملف الصحيح يأتي فقط من رابط التنزيل داخل النطاق الرسمي وتطابق بصمته المنشورة. عند وجود إصدار أحدث يثبت فوق السابق بالتوقيع نفسه ويحافظ على الجلسة والبيانات الخادمة. إذا اختلف التوقيع يتوقف النشر ولا يطلب من المستخدم حذف النسخة القديمة لتجاوز الخطأ.

## تحديث الأدلة

### دليل المستخدم

يحدث `دليل الزوار/الاستخدام` والأسئلة الشائعة ليشرحا:

- تنزيل APK وتثبيته وتحديثه والفرق بينه وبين اختصار PWA.
- تسجيل الدخول وتفعيل إذن الإشعارات وحل عدم وصول التنبيه.
- بدء محادثة فردية، إرسال الرسالة، معنى علامات الإرسال والقراءة، وعدد غير المقروء.
- الخصوصية: الطرفان فقط يقرآن المحادثة، ولا توجد مجموعات.
- الحظر والإبلاغ.
- صلاحية العضو في تعديل نفسه ووالده وأبنائه المباشرين، وإضافة أبنائه وترتيبهم، وسجل `تعديلاتي` والتراجع.
- معنى أرقام الإحصاءات والزيارات بعد ضبطها.

### دليل الإدارة

يحدث دليل الإدارة ليشرح:

- تنبيه العناصر التي تحتاج إجراء ومشاركة أكثر من مشرف في الطلب نفسه.
- صلاحيات `approve_members` و`approve_birth` و`reorder` و`edit_profile` ونطاق الفروع.
- صفحة سجل التعديلات وتراجع الإدارة ومعالجة التعارض.
- خصوصية الرسائل: الإدارة لا تقرأ المحادثات الخاصة، وترى الرسالة المبلغ عنها فقط.
- معالجة بلاغات المراسلات وإيقاف الحساب المسيء.
- إدارة مفاتيح Push وإصدار APK والتوقيع وصفحة التنزيل من الجانب التشغيلي، من دون عرض الأسرار داخل التطبيق.
- دقة الإحصاءات والزيارات والنسخ الاحتياطي ونقطة الرجوع قبل التفعيل.

يحدث كذلك `ALMFRJE_DEV_GUIDE.md` بالبنية التقنية الجديدة، والجداول، وسياسات RLS، وService Worker، ومسار إصدار APK، واختبارات التوقيع والتنبيهات. لا تعدل أدلة التطبيقات الأخرى في المستودع.

## البناء والتوقيع والنشر

يبنى Android في مشروع فرعي معزول باسم واضح داخل مستودع المفرجي، وتضاف GitHub Actions للإصدار فقط. خطوات الإصدار:

1. تشغيل اختبارات الموقع والصلاحيات والمراسلات والبناء.
2. إنشاء حزمة TWA من الإعداد المثبت.
3. بناء APK إصدار وتوقيعه بالمفتاح المحفوظ في أسرار GitHub.
4. التحقق من `package name` و`versionCode` و`versionName` وشهادات التوقيع.
5. حساب SHA-256 للملف النهائي.
6. نشر إصدار GitHub ورفع APK وملف checksum وملاحظات الإصدار.
7. تنزيل الأصل المنشور من GitHub ومقارنة SHA-256 مع الملف المبني؛ لا يكفي نجاح workflow.
8. تحديث بيانات صفحة التنزيل إلى الإصدار المتحقق منه، ثم نشر الموقع والتحقق من الرابط الحي.

يحفظ مفتاح التوقيع خارج المستودع مع نسخة احتياطية مشفرة؛ فقدانه يمنع تحديث التطبيق المثبت. لا يطبع workflow المفتاح أو كلمات مروره، ولا يعمل إصدار الإنتاج من طلبات سحب غير موثوقة.

## ترتيب التنفيذ والنشر

1. إكمال تقوية الصلاحيات والبوابة وفق التصميم الأمني السابق واختبارها خارج الواجهة.
2. إنشاء مخطط المراسلات وRLS وواجهات الخادم واختبار طرفين وطرف ثالث وحساب موقوف.
3. بناء واجهة الرسائل وRealtime والعداد والحظر والإبلاغ.
4. إضافة Service Worker وPush واختبار وصول التنبيه وفتح المحادثة.
5. إنشاء TWA وDigital Asset Links وبناء APK موقّع واختباره.
6. تحديث دليلي المستخدم والإدارة والأسئلة الشائعة والدليل التقني.
7. إنشاء صفحة التنزيل، ثم نشر الإصدار المتحقق منه وربط الصفحة به.

قبل كل تغيير حي تؤخذ نسخة احتياطية ونقطة رجوع وفق الإجراء المعتمد. ينشر مخطط المراسلات قبل الواجهة بصورة متوافقة، ولا يحذف أو يغير جداول المناقشات الإدارية الحالية. إذا فشل اختبار أمني أو توقيع أو تنبيه، يتوقف التفعيل ولا ينشر رابط APK.

## الاختبارات

تكتب اختبارات الفشل أولًا وتغطي:

### الصلاحيات والخصوصية

- العضو المفعّل يستطيع إنشاء محادثة مع عضو مفعّل آخر فقط.
- الزائر والعضو الموقوف وغير المفعّل لا يقرأون أو يرسلون أو يشتركون في Push.
- طرفا المحادثة فقط يستطيعان قراءة رسائلها، ويفشل عضو ثالث حتى مع معرف صحيح.
- الأدمن والمشرف لا يستطيعان قراءة محادثة خاصة ليسا طرفًا فيها.
- لا يقبل الخادم مرسلًا مزورًا أو محادثة بطرف ثالث أو محادثتين للزوج نفسه.
- الحظر يمنع الإرسال في الاتجاهين ولا يكشف رسائل جديدة.
- البلاغ يقبل رسالة من محادثة المبلغ فقط ويحفظ اللقطة المحدودة الصحيحة.
- RLS المباشرة تعطي النتائج نفسها التي تعطيها واجهات الخادم.

### الرسائل والتزامن

- تحفظ الرسالة مرة واحدة عند إعادة محاولة معرف الطلب نفسه.
- يصل الحد الأقصى 2000 حرف ويرفض ما بعده والنص الفارغ.
- تمنع حدود المعدل الإساءة من دون تعطيل القراءة.
- يرتب وقت الخادم الرسائل، ويتحدث آخر نشاط وعدد غير المقروء ذريًا.
- يحدّث فتح المحادثة مؤشر قراءة الطرف الحالي فقط.
- يعمل Realtime للمشاركين ولا يسرب حدثًا أو جسم رسالة إلى غير المشاركين.
- لا يوجد مسار أو زر أو جدول يسمح بإنشاء مجموعة.

### الإشعارات

- لا يسجل اشتراك Push إلا لصاحب الجلسة المفعّل.
- لا يحتوي التنبيه نص الرسالة ولا يرسل للمرسل.
- الضغط على التنبيه يفتح المحادثة المطلوبة بعد التحقق، أو شاشة الدخول إذا انتهت الجلسة.
- لا يظهر تنبيه نظامي عندما يكون المستقبل داخل المحادثة نفسها وواجهة التطبيق ظاهرة.
- تنظف الاشتراكات المنتهية، ولا يؤدي فشل Push إلى فشل حفظ الرسالة.
- يظهر غير المقروء عند العودة حتى إذا لم يصل Push.
- رفض إذن الإشعارات لا يمنع استخدام المراسلات.

### APK والتنزيل

- يطابق APK معرف الحزمة والإصدار المعتمدين ويجتاز تحقق التوقيع.
- تطابق بصمة الشهادة `assetlinks.json`، ويفتح TWA النطاق الرسمي من دون شريط متصفح.
- تفتح الروابط الخارجية خارج التطبيق ولا يستطيع نطاق آخر الظهور داخله بوصفه المفرجي.
- يثبت APK على جهاز أو محاكي مدعوم، ويحدث فوق إصدار سابق موقع بالمفتاح نفسه.
- يفتح رابط التنزيل الأصل المنشور فعلًا، ويطابق SHA-256 المعروض الملف المنزل من GitHub.
- لا يحتوي APK أو JavaScript العام أسرار التوقيع أو VAPID الخاص أو مفتاح الخدمة.

### الأدلة وتجربة العرض

- يحتوي دليل المستخدم خطوات التنزيل والتثبيت والإشعارات والمراسلات والخصوصية والتراجع.
- يحتوي دليل الإدارة الصلاحيات وسجل التعديلات والبلاغات والنشر الآمن.
- تبقى الأدلة متاحة حسب الدور ولا تكشف تعليمات أو بيانات إدارية للزائر.
- تظهر صفحة التنزيل بصورة سليمة على الهاتف والحاسب وتبقى قابلة للاستخدام قبل تسجيل الدخول.

تضاف إلى ذلك `npm test` و`npm run check:boundaries` وبناء Next.js/OpenNext، واختبار رابط Cloudflare العام، واختبار APK النهائي المنشور لا الملف المحلي فقط.

## معايير القبول

- يستطيع عضوان مفعّلان تبادل رسائل نصية فردية فورًا، ولا توجد مجموعات أو طريق تقني لإضافة طرف ثالث.
- لا يستطيع غير طرفي المحادثة قراءة محتواها، بما في ذلك الإدارة، إلا لقطة رسالة أبلغ عنها أحد الطرفين.
- يظهر عدد غير المقروء وحالة القراءة بصورة صحيحة بعد الإرسال والتحديث وإعادة الدخول.
- يصل تنبيه Android باسم المرسل ومن دون نص الرسالة بعد منح الإذن، ويفتح المحادثة الصحيحة.
- يبقى وصول الرسالة والعداد صحيحين إذا فشل التنبيه أو كان الإذن مرفوضًا.
- APK موقّع ويطابق الحزمة والإصدار والشهادة، وDigital Asset Links صالح.
- يوجد رابط تنزيل ثابت يعمل من الموقع الحي، مع الإصدار والحجم وSHA-256 وتعليمات تثبيت وتحديث صحيحة.
- يعاد تنزيل APK المنشور والتحقق من بصمته وتوقيعه قبل عرض الرابط للمستخدمين.
- يغطي دليل المستخدم ودليل الإدارة والأسئلة الشائعة كل الميزات المعتمدة، بما فيها الصلاحيات والتراجع والتنبيهات والمراسلات وAPK.
- تنجح مصفوفة الصلاحيات والاختبارات والبناء والفحص الحي، وتوجد نسخة احتياطية ونقطة رجوع قبل التفعيل.
